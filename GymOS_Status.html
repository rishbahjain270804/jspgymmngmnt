Next Steps — In Order

01
Get the 5 blocking answers from OAN Plan prices, GSTIN, branch access model, discount cap, who can extend expiry. These 5 answers unblock seed data and the RBAC code.
02
Write the database schema (Postgres SQL) CREATE TABLE for: branches, members, plans, memberships, checkins, payments, invoices, equipment, expenses, measurements, staff, roles. branch_id as FK on every operational table.
03
Scaffold the monorepo pnpm workspace: apps/web (React+Vite), apps/desktop (Tauri), apps/mobile (Expo), apps/api (Node+Fastify), packages/core, packages/ui.
04
Build packages/core first Expiry calculation, GST split, status derivation (active/expiring/expired), the can(user, permission, resource) RBAC helper, Zod schemas. This is the rule that makes all three shells right at once.
05
Seed data before any UI ~50 realistic OAN members, 8 programs, 2 branches with different profitability, backdated check-ins, various payment states. The demo only lands if the data looks alive.
06
Build Check-in first (hero moment) The screen OAN will use 200+ times a day. QR scan + phone lookup → green/amber/red verdict. This is the demo moment. Build it until it's sub-2-second and works on all three shells.
07
Then: Members → Payments → Dashboard In that order. Accounts (P&L) and Equipment (roll-up pattern) are the last two — they're the most impressive to owners but depend on Payments being complete.
08
RBAC demo moment: 3 logins live Admin (all branches + revenue), Branch Manager (one branch + revenue), Front Desk (same branch, money hidden). Switch live during the demo. This is a selling point, not a technical detail.
